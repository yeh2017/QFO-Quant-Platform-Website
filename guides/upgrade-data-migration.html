Version Upgrade

更新到新版本，如何复制并迁移原有数据

升级 QFO 不需要重新拉取全部历史数据。先停止旧版和新版，再把旧数据库复制到新版后端目录。

核心原则：旧版和新版 QFO 必须完全停止运行，数据库必须在新版后端首次启动前复制到位。

一、迁移前准备

  1. 关闭旧版和新版 QFO 的所有窗口，确认 Python、Node.js 和 QFO 后端均已停止。
  2. 下载并完整解压最新稳定版，不要直接覆盖旧版本文件夹。
  3. 保留旧版本目录和数据库备份，确认迁移成功后再自行归档。

二、复制数据库

  1. 在旧版本中找到 backend/quant_data.db。
  2. 如果新版本的 backend/ 已有同名数据库，先备份。
  3. 将旧版数据库复制到新版目录，最终路径必须是 backend/quant_data.db。

三、选择正确的启动脚本

新版本目录状态启动方式
新下载，尚未安装 Python 和 Node.js 依赖运行 run_first_time.bat
已经完成依赖安装运行 run_quick_start.bat

四、如果存在 WAL 文件

正常关闭 QFO 后，通常只需复制 quant_data.db。如果仍然存在 quant_data.db-wal 或 quant_data.db-shm，不要在数据库写入过程中复制，也不要只复制其中一个文件。先确认所有相关进程已经停止，再将数据库相关文件作为同一组处理。

quant_data.db-wal 可能包含尚未写回主数据库的数据；quant_data.db-shm 通常可以由 SQLite 重新生成。

五、迁移后检查

  1. 进入数据中台，检查最新日期、数据量和同步水位。
  2. 执行一次日常增量同步，确认旧数据可以继续更新。
  3. Token、API Key 不保存在数据库中，如有需要请在设置页重新填写。

建议迁移到相同版本或更新的稳定版本，不要把新版本数据库复制回旧版本程序。
